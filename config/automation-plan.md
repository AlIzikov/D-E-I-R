# План автоматизации D-E-I-R

## Цель

Организовать асинхронную работу Developer и Auditor через GitHub и последующее подключение Z.ai.

## Этап 1 — Репозиторий

- [ ] Создать и проверить инструкции агентов.
- [ ] Создать шаблоны reports и reviews.
- [ ] Проверить формат сообщений.
- [ ] Убедиться, что секреты исключены из Git.

## Этап 2 — GitHub

- [ ] Настроить безопасную аутентификацию.
- [ ] Выдать агентам минимально необходимые разрешения.
- [ ] Реализовать чтение новых сообщений.
- [ ] Реализовать создание новых отчётов и отзывов.
- [ ] Добавить защиту от повторной обработки.
- [ ] Обработать конфликты и ошибки API.

## Этап 3 — Z.ai

- [ ] Проверить актуальную документацию API.
- [ ] Проверить доступность выбранной модели.
- [ ] Настроить секрет API через переменные окружения или хранилище секретов.
- [ ] Проверить вызов модели на минимальном примере.
- [ ] Только после успешного теста подключить агентские сценарии.

## Этап 4 — Планировщик

- [ ] Выбрать среду запуска: GitHub Actions, сервер или поддерживаемый планировщик Z.ai.
- [ ] Настроить отдельные запуски Developer и Auditor.
- [ ] Предусмотреть защиту от параллельной обработки.
- [ ] Добавить ограничение числа действий за один запуск.
- [ ] Настроить повторные попытки при временных ошибках и ограничениях частоты.
- [ ] Проверить журналы и оповещения об ошибках.

## Этап 5 — Испытания

- [ ] Проверить полный цикл отчёт → отзыв → исправление.
- [ ] Проверить отсутствие повторных сообщений.
- [ ] Проверить конфликт одновременных изменений.
- [ ] Проверить обработку ошибки API.
- [ ] Проверить отсутствие секретов в коммитах и логах.
- [ ] Проверить эскалацию человеку после трёх безуспешных циклов.

## Безопасность

- Не хранить токены в репозитории.
- Не использовать широкие разрешения, если достаточно узких.
- Не выполнять force-push.
- Не развёртывать и не публиковать изменения автоматически без отдельного разрешения.
- Не считать систему готовой, пока интеграции и тесты не проверены.

## Текущее состояние

План подготовлен. Автоматизация ещё не реализована. Способ запуска и интеграции нужно подтвердить перед созданием рабочих конфигураций.
